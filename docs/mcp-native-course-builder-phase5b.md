# Phase 5B — direct draft cover upload rehearsal

Based on the verified deployed Phase 5A.1 commit, not the undeployed Phase 5A.2 browser-diagnostics patch. Adds one tool `upload_draft_course_cover` and separate `mcp:media` consent; older tokens retain their exact permissions. Only local/testing/staging with the existing curriculum rehearsal gate, separate media rehearsal switch and GD extension. Production is explicitly closed. No live activation in this release.

Input: exact 1920x1080 PNG/JPEG/WebP bytes, canonical base64, at most 512 KiB decoded, sanitized by GD pixel re-encoding; output at most 2 MiB. PNG remains PNG; JPEG/WebP normalize to JPEG (WebP transparency is not preserved). No URLs, caller file paths, data URIs, SVG, video, replacement, publication or arbitrary files. A server-generated random path is conditionally created in existing private managed storage and a native library record is attached to the owned unpublished course. Existing authorization locks and idempotency receipts protect the write. The transport reconciles uncommitted objects after the outer DB transaction; uncertain commit/query failures are logged without secrets for operator review. Sudden worker termination or storage outage may still require orphan reconciliation before production promotion.

Acceptance: signed-token tests, invalid image rejection, idempotency, no replacement, old-token scope challenge and production closed. Local fake storage is exercised; actual R2/S3 adapter and failure-injection rehearsals, live PHP-GD verification, request-size limits and client binary transfer support remain required before production activation.
